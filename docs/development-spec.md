# Clipboard History 重构开发与测试规范

版本 0.5 · 2026-10-14 · Windows 首发，保留 Linux 路径。当前基线：Qt 6.11.1、Qt Quick/QML、C++17、MinGW 13.1、SQLite schema v5；Windows 热键使用 Win32 RegisterHotKey，未引入 QHotkey。

## 1. 不可破坏的规则

- 剪切板回调只取快照、分类、入队；不做 SQL、图片编码/哈希、大文件 I/O，不同步等待。
- SQLite 连接固定归属一个工作线程；QML 不直接访问 DB 或文件。
- 图片先写临时文件、原子替换；DB 引用提交后才清理旧图。失败或退出不得丢失已确认记录。
- 运行数据默认位于可执行文件旁的 data/；用户可在设置中改选可写空目录。配置、SQLite、图片和日志统一放在该数据根目录；程序目录旁只保留 ClipboardHistory.ini 路径指针。设置路径时只保存待切换目标；下次启动且数据库/日志句柄打开前，才复制到空目录并更新活动路径。迁移失败时回滚本次复制、保留源目录并继续使用原路径，待切换目标保留供修正或重试；旧项目数据导入仍只读，绝不移动、覆盖、删除源数据。安装到 Program Files 等不可写目录时必须明确失败，不回退到系统用户目录。
- 日志只记事件、耗时、计数、错误码；不记录剪贴板正文、图片内容、完整私人路径。
- 已知部署风险：软件目录不可写（如 Program Files）时，Windows 会提示错误并退出；应用不会回退到系统用户目录。应将便携程序放在可写目录，或在受支持的部署设计中明确指定可写数据根。
- 已知运行风险：若目标目录在选择后被其他程序占用或失去写权限，启动迁移会失败并继续使用原路径；用户需修正目标后重试。未来若支持运行期迁移，必须先停止采集、排空队列并关闭数据库/日志连接。
- C++ QAbstractListModel 分页/增量供 QML ListView；delegate 不查询、解码或阻塞。
- 定时保留默认 0（永久），范围 1–87600 小时（最多 3650 天）；仅删除最近采集时间严格早于 UTC 截止点的非收藏记录，恰好等于截止点仍保留。采集同内容续期；收藏永不被该策略删除，文件源永不删除。启用/改期限/启动后检查，运行期间每分钟检查；后台事务最多 500 条，提交后仅删失去全部引用的应用图片。关闭阻止后续批次，不恢复已提交的删除。
- 总条目上限默认 0（无限制）；启用后统计全库，按最近采集时间和 ID 从旧到新删除非收藏。收藏数超过上限时保留收藏；与时长策略共用每批最多 500 条的事务、引用保护和总数刷新路径，采集/导入/取消收藏及周期检查后执行。见 [最终交接](handoffs/QUANTITY-LIMIT-RELEASE-2026-10-14.md)。
- 设置页异步按需创建并保留实例；启动偏好和平台注册留在根窗口。确认弹窗首次使用才创建，离开设置必须取消快捷键录制并恢复原快捷键。
- 应用管理的 Qt QML/图形缓存放在当前数据目录的 `cache`，禁用默认系统管线缓存；缓存目录失败时关闭运行时磁盘缓存，不回退系统目录。中文路径、首次保存/下次读取和失败分支必须回归。
- 性能仅用合成数据。Windows/Linux 单独建基线。

## 4. 测试矩阵与门禁

| 层级 | 内容 | 通过标准 |
|---|---|---|
| 单元 | MIME、去重、保留、配置、搜索参数 | 确定性、含边界错误；不碰真实剪贴板/用户目录/网络 |
| 数据集成 | 临时 SQLite、迁移、事务、图片引用 | 独立临时根；DB 行、文件、引用清理一致 |
| 模型/UI | Qt model tester、Qt Quick Test、交互/可访问性 | 无非法模型通知；键鼠主流程可用，错误态可恢复 |
| 平台 | Windows 剪贴板、托盘、热键、自启动、退出 | 隔离账户/VM；记 OS；不操作真实历史库 |
| 故障/隐私 | 磁盘满、拒绝、进程中断、坏旧库、日志扫描 | 可解释可恢复、源不丢、canary 不进日志/崩溃报告 |
| 压力/长稳 | 高频写、批量分页搜索、图片导入、30 分钟运行 | 无丢错记录、死锁、持续内存增长、长冻结 |

门禁顺序：格式/静态检查 → Debug 单测/集成 → Release x64 构建 → UI/平台回归。任一失败阻断合并。日志不可输出剪贴板样本。

## 5. 独立性能基准模块

### 隔离与固定数据

单独 runner + 新建临时数据根 + 合成数据。启动先规范化路径，验证其位于本次临时根；指向用户配置/旧项目目录或验证失败则拒绝。不得读真实剪贴板、用户 DB、旧图片；清理只删本次临时根。

固定随机 seed 和生成器版本。生成 10k/100k/500k 条：70% 文本、20% 图片引用、10% 本地文件路径；文本 32B/1KB/16KB；图片夹具 1080p/4K。

| 场景 | 操作与指标 |
|---|---|
| 采集/落盘 | 纯/重复/唯一文本及 1080p/4K 图；回调快照入队，入队到提交 P50/P95/P99，失败数和去重命中率 |
| 首屏 | 100k/500k 启动与开列表；启动到可交互、首 50 行耗时；冷/热分开 |
| 滚动 | 60 秒；帧时长、>33.3ms 帧比例、>100ms 冻结、峰值 RSS |
| 搜索 | 固定查询集跑 100k/500k；服务/结果可见分位数、正确率；debounce 单列 |
| 维护 | 500k 保留/孤儿清理；耗时、行文件一致性、删除数、错误数 |

### 首版候选阈值（不是已测结果）

Ref-01 冻结后连续三轮建立基线，再成为发布门槛。

| 指标 | 候选线 | 计时范围 |
|---|---:|---|
| 回调 | P95 ≤ 10ms | 通知至快照入队，不含后台持久化 |
| 文本落盘 | P95 ≤ 100ms | 入队至事务提交，Release/SSD |
| 4K 图片 | P95 ≤ 2s | 入队到原子落图且 DB 引用提交 |
| 首屏 50 行 | 100k 热进程 P95 ≤ 400ms；进程冷启动 ≤ 800ms | OS 文件缓存分开记录 |
| 搜索 | 100k P95 ≤ 200ms；500k ≤ 500ms | 查询到模型可见；debounce 前服务时间另报 |
| 滚动 | 60Hz 下 P95 帧 ≤ 16.7ms；>33.3ms 帧 ≤ 1%；无 >100ms 冻结 | 60 秒，头尾各 2 秒预热不计 |
| 内存 | 浏览 500k 后稳定 RSS ≤ 300MB | 搜索/滚动 5 分钟，报峰值末值及趋势 |
| 清理 | 正确性 100%；较同机基线退化 ≤ 10% | 500k；耗时按硬件报，不设跨磁盘绝对值 |

### 运行/判定/归档

1. Ref-01 候选：Windows 11 x64、4 核/8 线程、8GB、集显、SSD、60Hz。冻结时记录 CPU/GPU/驱动、内存、磁盘、OS、Qt、编译器、构建类型。Linux 另设机器和基线。
2. Release x64、无调试器、接电性能模式。每场景预热 1 次，至少 30 样本，3 个独立进程；报中位数/P95/最大值/失败数。
3. 同机、供电、分辨率、seed、构建选项比较。超绝对门槛或相对已通过基线退化 >10% 即失败；排除噪声后复测一次，仍失败阻断合并。
4. 归档 CSV、摘要 JSON、环境清单、提交 SHA、runner 版本、结论；不含真实剪贴板数据。

## 6. 首版验收清单

- 三类数据可记录/展示/再次复制；回调和 UI 线程不做 SQL、图片编码、大文件 I/O。
- 分页、搜索、键盘、加载/空/错误态稳定；无系统标题栏窗口可拖动并可隐藏，暗色、浅色、北极光和自定义主题可切换。
- 统一顶栏提供主页/设置导航和全局快捷键，不显示监听状态。
- 搜索框位于分类筛选上方；分类有图标；历史记录使用清晰分隔的卡片，图片默认以缩略图显示；源文件缺失时在对应记录行内显示状态。
- 分类按钮的图标与文字成组水平/垂直居中；历史列表的上下留白为固定布局间距，滚轮到达首尾时不能继续越界，短列表也不能滚出额外空白。
- 写入失败可恢复，DB/图片引用一致。
- 去重、保留上限、孤儿清理有自动测试；隐私 canary 不进日志。
- 旧库可重试核对且源不变；窗口尺寸、系统缩放、干净 Windows 安装可用。
- Windows 开机启动默认关闭；启用后登录启动到托盘，禁用后移除当前用户启动项。
- 设置或启动时快捷键注册失败必须弹窗，显示尝试的组合键、占用或系统错误原因、原快捷键恢复结果；提供“知道了”和“修改快捷键”。登录启动到托盘时发生失败也要显示窗口和弹窗。失败不保存新的组合键。
- 外观主题预览固定为 180×166 个逻辑像素，宽度变化时按 8px 间距自动换行；不显示 `custom-theme.json` 编辑说明。导入主题命名后存入程序目录的 `themes/*.json`，启动时读取；旧 `Appearance/importedThemesJson` 仅用于迁移，全部文件保存成功后才清除旧数据。
- 测试矩阵通过；Ref-01 冻结后性能门槛通过，报告归档。

## 8. 多对话协作与交接规则

### 何时拆分

- 任务可按相对独立的模块或阶段并行时，允许创建多个工作对话；例如数据层、采集/平台、QML UI、迁移/性能基准。
- 一个对话指定一个模块负责人和明确边界。开始前发布任务说明：目标、输入/输出接口、允许修改的目录/文件、依赖、验收项、是否可改公共接口。
- 公共接口、schema、跨模块文件先由主任务确定；并行任务不得各自改同一接口或重叠文件。确需修改时先向主任务提交提案并等待协调。
- 任务有依赖时按顺序交接：接口/数据契约先定，再分配实现；集成任务负责解决跨模块冲突。工作区共享时更要避免同时编辑同一文件；适合时使用独立分支/工作树。

### 任务完成文档

每个对话完成或暂停模块工作时，必须提交一份任务交接文档，统一放在 `docs/handoffs/`，文件名建议 `<阶段>-<模块>-<主题>.md`，以模板 [任务交接模板](handoffs/TASK-HANDOFF-TEMPLATE.md) 为准。文档必须包含：

1. 目标和完成状态（完成/部分完成/阻塞），以及明确未完成项。
2. 改动文件及用途；接口/schema/配置决策与兼容影响。
3. 执行过的构建、测试、基准命令和结果；未执行的检查明确写“未运行”，不得推断通过。
4. 已知问题、风险、复现步骤，以及依赖的其他模块/任务。
5. 接手者下一步可直接执行的步骤和建议验收命令。

主任务集成前先读交接文档并核对真实 diff 与测试结果；发现文档和代码不一致时以代码/实际运行结果为准，并更新交接说明。所有并行模块集成后，再产出统一集成报告。

### 对话长度与上下文续接

- 预计任务即将跨越多个大阶段、目标转变或上下文过长时，负责人应尽早建议拆成新对话或按模块新开对话；不要等到重要约束和决策无法可靠追溯。
- 新对话启动消息必须附当前开发文档、对应模块任务说明、最新交接文档、相关决策和待办；不得只说“继续上次工作”。
- 原对话先把已知状态写入交接文档，再转交；新对话读完文档后复述其负责边界、完成标准和未决问题，再开始改动。
- 如果当前工作仍可在原对话中安全完成，就无需为了形式而拆分；拆分的目的是并行独立工作或可靠续接。

## 9. 开源同类项目对标与可借鉴点

### CopyQ（首要技术参考）

- 仓库：[hluk/CopyQ](https://github.com/hluk/CopyQ)；架构：[Source Code Overview](https://github.com/hluk/CopyQ/blob/master/docs/source-code-overview.rst)；安全说明：[Security](https://github.com/hluk/CopyQ/blob/master/docs/security.rst)；测试环境示例：[AGENTS.md](https://github.com/hluk/CopyQ/blob/master/AGENTS.md)。
- 它是 C++/Qt 项目，支持 Windows、Linux、macOS，功能包含多 MIME、筛选、标签、热键、脚本和自定义命令。它的 UI 偏 Qt Widgets；我们借鉴其行为和边界设计，不照搬界面。
- **值得借鉴：**把平台特定代码集中到 platform adapter；明确剪贴板监控、主窗口、IPC/客户端的职责；按格式处理 MIME；支持忽略特定来源；对操作敏感剪贴板格式（如密码管理器标记）采取默认不保存；测试进程固定独立设置/数据目录，避免碰用户数据；跨平台 CI 和显式测试分组。
- **线程注意：**CopyQ 文档说明其将 clipboard monitor 放到独立进程，原因是 Qt 的 clipboard 访问可能阻塞 UI，且访问通常要求在 GUI 线程。新项目先在 Qt GUI 线程快速取得 MIME 快照，再把编码、哈希、持久化投递后台；不要把 QClipboard 对象直接移给任意工作线程。只有实测发现监控隔离/崩溃恢复有收益后，才评估独立 monitor 进程及 IPC。
- **不必首版照搬：**脚本引擎、插件系统、多 tab、客户端/服务端和多进程命令系统会扩大维护面；先以稳定 C++ 模块接口满足首版。Qt Widgets 也不是我们选 QML 后必须沿用的 UI 方案。
- CopyQ 使用 GPL-3.0-or-later。借鉴功能思路和公开协议与复制其代码是两件事；若拟复制/改编源代码，先做许可证兼容审查。

### Ditto（Windows 产品行为参考）

- 仓库：[sabrogden/Ditto](https://github.com/sabrogden/Ditto)。
- 它聚焦 Windows 剪贴板历史，保存剪贴板多种格式到本地数据库，提供托盘、全局热键、快速选条目并回到先前应用粘贴；项目公开说明为本地优先、不要求登录、不做云同步或遥测。
- **值得借鉴：**Windows 首发时重点验证热键冲突、目标窗口恢复/粘贴、托盘入口、安装版和便携版、长历史搜索与本地数据可迁移。把这些列为平台验收场景，而不只测“列表里能看见记录”。
- 它不是 Qt/QML 跨平台架构的直接模板；平台机制和项目技术栈不应与本项目的 C++/Qt 分层混为一谈。
- Ditto 使用 GPL-3.0。复制代码前同样须确认许可证义务。

### 对本项目的结论

仍采用当前方案：Qt Quick/QML 做 UI、C++ 管平台/模型/业务、SQLite 管元数据，后台任务处理图像与持久化。参考 CopyQ 的平台边界、clipboard 安全处理和测试隔离；参考 Ditto 的 Windows 使用流程。暂不引入脚本/插件或多进程架构；以性能和稳定性测量决定是否需要更复杂的隔离。
