DEVELOPMENT BRIEF / 01

把剪切板历史
做成可靠的日常工具

新项目开发方案。保留 Qt 和剪切板工具的核心价值，重建采集、存储与界面边界，让性能、隐私和后续功能都能稳步演进。

QT 6C++ 17+SQLITEWINDOWS FIRST / LINUX POSSIBLE

版本 0.1　·　2026 年 10 月 10 日　·　基于旧仓库源码评估

核心建议

新建应用骨架和模块边界，按阶段重做核心；复用旧项目经过验证的产品行为与 QHotkey 思路。旧数据库和图片先导入、核对，再决定迁移完成。

01 / DIRECTION

保留经验，不继承旧耦合

旧程序已经跑通“监听 → 保存 → 浏览 → 再复制”的主链路。新项目可以重做应用结构，不必在旧窗口类和清理线程上继续叠功能。

建议路径

新骨架 + 有计划的迁移。
使用 Qt 6 + Qt Quick/QML + C++ + SQLite。QML 是声明式 UI 语言，Qt Quick 是用它构建界面的框架与类型库，两者配合使用；C++ 负责剪切板、托盘、热键、SQLite 和耗时任务。

判断依据

采集、磁盘 I/O、数据库、托盘、配置和窗口逻辑集中在少数类中。性能升级与 UI 换代会反复碰到同一边界；先建立清楚的模块接口更容易控制回归。

沿用

  • Qt 应用、系统托盘和 QHotkey 能力
  • 文本、图片、本地文件三类历史
  • SQLite 本地保存与图片哈希去重
  • 历史数量上限和点击后重新复制

重做

  • 回调中同步编码图片和写数据库
  • 每条记录都创建清理线程
  • 硬编码数据路径和覆盖配置默认值
  • 把剪切板正文写进日志

02 / ARCHITECTURE

系统能力、数据与界面各自负责

剪切板事件快速入队；数据库由固定工作线程访问；界面模型接收分页结果与状态。

Qt Quick + QML

适合高度定制、简洁精致、带轻量动效的界面；样式和布局可更快迭代。Qt Quick 的场景图可利用图形加速，但不代表数据库或业务逻辑自动变快。

Qt Widgets

更适合传统密集桌面控件和既有 Widgets 项目，C++ 工作流直接。深度改视觉也能做到，但自绘与样式维护通常更多。

01 / OS

系统入口

启动、托盘、QHotkey、自启动与退出生命周期。

02 / CAPTURE

剪切板采集

读取 MIME 快照、识别类型、排除应用自身回写。

03 / CORE

历史服务

去重、保留策略、固定队列和错误状态反馈。

04 / STORAGE

本地存储

SQLite、图片文件、迁移版本和目录管理。

05 / UI

QML 界面

搜索、筛选、历史列表、设置与状态页面。

数据流：系统剪切板 → Capture → 队列 → HistoryService → SQLite / ImageStore → QML Model。

框架选择

推荐 Qt 6 + QML 作为新 UI 起点，C++ 保持系统集成与数据处理。快速原型若证明 Widgets 能满足设计目标，可再调整；不要并行维护两套 UI。

03 / PERFORMANCE & DATA

先消除阻塞和无界工作

区域设计决定预期效果
剪切板事件回调只读取必要快照并入队；图片编码、哈希、落盘在后台执行。复制大图时窗口仍可响应。
SQLite连接在线程内创建和使用；固定写入队列批量处理，不为每条记录启动线程。避免线程抖动与连接竞态。
历史列表C++ 提供 QAbstractListModel；QML 用 ListView 只创建可见委托，按页从后台取数；筛选字段建索引，搜索使用绑定参数。大量历史记录不一次性变成大量 QML 对象，滚动和检索更稳定。
图片文件内容哈希命名，临时文件写完再原子替换；数据库成功后发布记录。减少半文件和库/文件不一致。
重复条目再次复制时更新最近使用时间，而非静默丢弃。排序体现真实使用频率。

数据边界

元数据放 SQLite；大图片放应用数据目录；文件剪切板只存路径，不复制用户原文件。Schema 变更使用显式迁移版本。

隐私默认值

普通日志不记录剪切板正文、文件名或私人路径。明确告知持续监听并提供清除历史入口；加密、同步、敏感应用排除规则待产品决策。

04 / EXPERIENCE

让常用操作一眼可见、键盘可达

主窗口首先服务“找到刚复制的内容并再次使用”。界面层级围绕搜索、类型筛选、最近记录和设置展开；类型同时使用文字标签，不只依赖颜色。

首版交互

  • 无系统标题栏的紧凑窗口；支持拖动、全局热键呼出/隐藏，托盘仅提供显示窗口和退出
  • 统一顶栏切换历史/设置；搜索框位于分类筛选上方
  • 点击或键盘确认复制，并显示成功反馈
  • 空列表、加载、错误、无结果均有明确说明

质量要求

  • 暗色、浅色、北极光和自定义主题；JSON 导入需命名并新增主题选项
  • 键盘导航、可见焦点和合理焦点返回
  • 适配系统缩放、窗口尺寸和高对比度
  • 搜索后展示带图标的类型筛选；图片记录默认以缩略图呈现
  • 历史记录以圆角卡片呈现，操作入口清晰；展开/收起只显示文字，源文件缺失状态显示在对应行
  • 文件源可用状态由 C++ 模型提供，QML 不直接检查文件系统
  • 统一间距与语义色，避免重阴影和装饰渐变
  • 按视觉约定检查层级、状态和内容密度

05 / MIGRATION

导入可重复、可核对；不覆盖旧目录

  1. 1DISCOVER

    定位旧数据

    识别旧 SQLite 和 images 目录，展示来源并让用户确认。

  2. 2BACKUP

    先备份再导入

    只读打开旧库；记录批次；复制图片并校验哈希。

  3. 3VERIFY

    核对数量和引用

    检查条数、类型、时间、图片和孤儿引用；重复导入不产生重复数据。

  4. 4KEEP

    确认成功后再清理

    迁移失败可安全重试；旧库和原图保留，除非用户确认清理。

保护原则

旧版存在配置路径和数据路径混用，不能假设图片都在同一个目录。缺失图片要报告；不能删除源库或原文件。

07 / ACCEPTANCE

首版完成标准

  • 文本、图片、文件均可展示和再次复制
  • 大图处理和数据库维护不阻塞 UI
  • 搜索、筛选、分页和键盘操作一致
  • 写入失败时显示可理解的错误状态
  • 历史限制生效，清理不遗留无主图片
  • 日志不包含剪切板正文或私人路径
  • 旧库可重复导入，结果可核对且不覆盖源数据
  • 小屏、常见窗口尺寸及系统缩放下仍可操作
  • 无标题栏窗口可拖动和隐藏，四种主题可切换
