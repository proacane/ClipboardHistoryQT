# 首屏与便携缓存优化交接（2026-10-13）

## 状态和范围

已完成实现、Release 构建、界面回归和六轮隔离性能复测。此次优化针对上一轮发现的隐藏设置页、确认弹窗提前创建，以及 Qt 默认缓存路径；不修改数据库格式、搜索算法或真实剪贴板采集。

完整性能验收仍未通过：启动计时不包含进程及 QGuiApplication 初始化，不能当作正式程序的端到端冷启动成绩；400 ms 热进程候选线、500k 搜索、真实系统路径、GPU Present 和数小时长稳仍需补证据。

## 改动及生命周期

- `src/ui/Main.qml`：设置页改为异步 Loader，首次打开才创建，显示加载提示；加载完成后保留实例，再次打开无需重建。启动偏好、主题、配置、平台注册 Connections 继续属于根窗口。
- 删除、清空及旧库导入确认弹窗改为按需 Loader。删除和导入入口统一经根窗口函数打开，弹窗仍以根窗口内容为父项。清空弹窗此前没有调用入口，本次保留其原有逻辑而不扩大功能范围。
- 快捷键错误弹窗能够等待设置页加载完成，再滚动到快捷键分区并聚焦录制按钮。离开设置页会取消录制、恢复原快捷键，并取消未执行的聚焦请求。
- `src/app/graphics_cache.h` 与 `src/app/main.cpp`：使用所选数据目录下的 `cache/qml` 和 `cache/pipeline.cache`。根窗口先以隐藏状态加载，在首次显示和渲染线程初始化前设置图形配置。应用禁用 Qt 自动系统管线缓存，其余窗口也不会回退到自动系统缓存。
- Windows 的 QML 缓存环境变量通过宽字符接口设置，支持中文路径；其他平台使用 UTF-8。首次没有管线缓存时只配置保存；存在缓存时再配置读取。缓存目录创建失败时保留 AOT 编译代码，关闭运行时磁盘缓存并给出诊断，不转存用户目录。数据目录本身不可写时的既有启动失败规则保持不变。
- `tests/acceptance/tst_qml_acceptance.cpp`：适配设置页独立创建上下文；新增按需创建/保留实例、首次聚焦/离页恢复、删除确认取消与接受、导入确认取消，以及缓存首次写入/下次读取、中文路径、目录创建失败回归。性能报告新增首次设置 Loader.Ready 耗时和保留实例再次打开耗时。

缓存属于可重建数据，数据路径下次切换后使用新位置。这里只约束应用管理的 Qt 缓存，不承诺改变操作系统或显卡驱动自身的缓存策略。配置 API 的使用参考 [Qt 图形缓存文档](https://doc.qt.io/qt-6/qquickgraphicsconfiguration.html) 和 [QML 磁盘缓存文档](https://doc.qt.io/qt-6/qmldiskcache.html)，构建与运行验证使用本机 Qt 6.11.1。

首轮各连续滚动约 60 秒，排除头尾 2 秒，使用真实窗口 `frameSwapped` 间隔，代表渲染完成代理，不能等同 GPU 执行或屏幕 Present。10k：7998 间隔，P95 7.72 ms，最大 21.38 ms；100k：7952 间隔，P95 7.80 ms，最大 69.23 ms，仅 3 个超过 33.3 ms（约 0.038%），无超过 100 ms 的间隔。100k GUI 心跳最大 66.21 ms。混合图片夹具仍仅复用两张简单图片，无法代表复杂图片密集滚动。

100k 场景真实队列处理 10 张复杂合成 4K 图，10/10 入库，最终总数 100010，最后一张完整解码像素一致。入队到观察提交 P50 844.73 ms，P95/最大 949.17 ms；对应 GUI 心跳最大 34.47 ms，无超过 100 ms。5 次大图展开 Image.Ready 观测上界 P50 175.97 ms、最大 224.85 ms，仍含主动等待，不等同首次图像呈现。
